# Guide de présentation commerciale — Dépann’Home Pro

## Démonstration commentée de 30 minutes auprès d’une entreprise

**Public visé :** dirigeants, responsables administratifs, responsables techniques, chefs d’équipe et futurs utilisateurs.

**Objectif :** montrer comment Dépann’Home Pro centralise le parcours d’une intervention, de la réception de la demande jusqu’au suivi administratif, tout en facilitant le travail au bureau et sur le terrain.

**Durée d’allocution : 30 minutes.** Les questions détaillées sont traitées après la démonstration.

---

## 1. Préparation avant le rendez-vous

### Matériel conseillé

- un ordinateur connecté à Dépann’Home Pro pour représenter le bureau ;
- un téléphone ou une fenêtre mobile pour représenter le technicien ;
- une connexion internet stable ;
- un dossier fictif déjà préparé ;
- quelques photographies techniques sans données personnelles ;
- un rapport PDF de démonstration ;
- une mission partenaire fictive ou Sandbox clairement identifiée.

### Données de démonstration à préparer

Créer avant la présentation :

- un client fictif : **Mme Camille Martin** ;
- une adresse d’intervention fictive ;
- un rendez-vous prévu le jour de la démonstration ;
- un devis simple comportant deux ou trois lignes ;
- un rapport technique partiellement renseigné ;
- une documentation technique dans la bibliothèque ;
- si nécessaire, une mission partenaire Sandbox.

Ne jamais utiliser de véritables coordonnées client, mots de passe, clés API, documents confidentiels ou données comptables réelles.

### Vérifications cinq minutes avant la présentation

- se connecter avec le bon compte de démonstration ;
- vérifier que les pages Clients, Planning, Facturation et Missions partenaires se chargent ;
- fermer les notifications personnelles du navigateur ;
- préparer les onglets ou appareils dans l’ordre du parcours ;
- vérifier l’affichage mobile ;
- masquer toute clé API ;
- conserver un PDF de rapport déjà généré en solution de secours.

## Séquence 1 — Introduction et enjeux

**Durée : 2 minutes**

### Écran affiché

Page d’accueil de Dépann’Home Pro.

### Texte proposé

> Bonjour et merci de me recevoir. Pendant les trente prochaines minutes, je vais vous présenter Dépann’Home Pro à travers un cas concret : une entreprise reçoit une demande, crée ou retrouve son client, planifie l’intervention, transmet les informations au technicien, réalise le rapport puis assure le suivi administratif.
>
> L’objectif de Dépann’Home Pro est de rassembler dans un même environnement les informations qui sont souvent dispersées entre le téléphone, les courriels, le planning papier, les fichiers bureautiques et différents logiciels.
>
> La démonstration sera volontairement opérationnelle. Plutôt que d’énumérer toutes les fonctions, nous allons suivre le parcours réel d’une intervention et observer ce que voient le bureau, le technicien et le responsable de l’entreprise.

### Message clé

**Une information saisie une fois accompagne toute l’intervention.**

### Transition

> Commençons par la manière dont l’application s’adapte aux différents collaborateurs de l’entreprise.

---

## Séquence 2 — Vue d’ensemble et rôles

**Durée : 3 minutes**

### Manipulations

1. Montrer l’accueil et les principaux accès.
2. Montrer rapidement la navigation vers Clients, Planning, Facturation, Bibliothèque et Missions partenaires.
3. Expliquer que l’affichage dépend du rôle de l’utilisateur.

### Texte proposé

> L’écran d’accueil donne accès aux fonctions quotidiennes sans multiplier les menus techniques. Chaque utilisateur retrouve uniquement les outils correspondant à sa mission.
>
> L’administrateur organise l’entreprise, le planning, les clients et les accès. Le poste administratif standard peut gérer l’activité opérationnelle. Le technicien et le chef d’équipe disposent des fonctions nécessaires sur le terrain. Un profil comptable peut accéder aux éléments financiers correspondant à son travail.
>
> Cette séparation évite de donner à chaque collaborateur un accès inutile à l’ensemble des données. Elle améliore à la fois la lisibilité et la sécurité.
>
> L’application est conçue pour fonctionner sur ordinateur et sur mobile. Le bureau conserve une vision globale, tandis que le technicien accède aux informations utiles à l’intervention.

### Messages clés

- une interface adaptée au rôle ;
- une continuité entre le bureau et le terrain ;
- moins de manipulations et moins de doubles saisies.

### Transition

> Prenons maintenant l’exemple de Camille Martin, qui contacte l’entreprise pour une intervention.

## Séquence 3 — Fiche client

**Durée : 4 minutes**

### Manipulations

1. Ouvrir la liste **Clients**.
2. Rechercher le client fictif.
3. Ouvrir sa fiche.
4. Montrer ses coordonnées, l’adresse d’intervention, les notes, les pièces jointes et l’historique.
5. Expliquer la recherche et l’archivage sans supprimer l’historique métier.

### Texte proposé

> La fiche client devient le point de référence de l’entreprise. Nous y retrouvons les coordonnées, l’adresse principale, l’adresse d’intervention, les informations utiles au dossier, les notes et les éventuelles pièces jointes.
>
> L’historique permet de comprendre ce qui s’est passé sans rechercher les informations dans plusieurs messageries ou classeurs. Lorsqu’une note importante est ajoutée, son origine et sa date permettent de replacer l’information dans son contexte.
>
> La recherche permet de retrouver rapidement un client. Si la relation est terminée, la fiche peut être archivée sans effacer les documents et interventions qui doivent rester conservés.
>
> Lorsqu’une mission arrive par un partenaire externe autorisé, Dépann’Home Pro peut également créer automatiquement la fiche client dans l’entreprise destinataire et la rattacher à la mission. Les essais Sandbox restent, eux, isolés des vrais clients.

### Messages clés

- dossier client centralisé ;
- traçabilité des informations ;
- conservation de l’historique ;
- création automatique possible depuis une mission API réelle.

### Transition

> Une fois la demande enregistrée, l’étape suivante consiste à organiser l’intervention.

---

## Séquence 4 — Planning et organisation

**Durée : 4 minutes**

### Manipulations

1. Ouvrir le **Planning**.
2. Créer ou ouvrir le rendez-vous de Camille Martin.
3. Montrer la date, l’horaire, l’adresse et l’affectation du technicien.
4. Montrer la liaison entre le rendez-vous et la fiche client.
5. Évoquer la mise à jour de l’intervention et la synchronisation des informations.

### Texte proposé

> Le planning transforme la demande en action. Le bureau choisit la date, l’horaire et le collaborateur affecté. Le rendez-vous reste lié au client : l’adresse et les informations nécessaires suivent donc le dossier.
>
> Le responsable peut visualiser l’organisation de l’équipe et éviter de transmettre les consignes séparément par téléphone. Le technicien retrouve ensuite son intervention depuis son accès mobile.
>
> Si la mission provient d’un partenaire, elle peut être acceptée puis planifiée dans le même environnement. Le suivi ne nécessite pas de recréer manuellement tout le dossier.
>
> L’intérêt est double : le bureau garde la maîtrise de l’organisation et le terrain reçoit une information structurée et à jour.

### Messages clés

- visibilité sur l’activité ;
- affectation claire ;
- continuité entre client, mission et rendez-vous ;
- réduction des oublis de transmission.

### Transition

> Passons maintenant du côté du technicien pour voir comment l’intervention est documentée sur le terrain.

## Séquence 5 — Intervention mobile et rapport technique

**Durée : 6 minutes**

### Manipulations

1. Passer sur l’affichage mobile.
2. Ouvrir l’intervention du technicien.
3. Montrer les informations client et les consignes.
4. Ouvrir le rapport technique.
5. Parcourir quelques sections du formulaire.
6. Montrer l’ajout d’une photographie ou d’une observation.
7. Expliquer la relecture et la validation.
8. Montrer un aperçu PDF déjà préparé.

### Texte proposé

> Sur le terrain, le technicien ouvre l’intervention qui lui a été attribuée. Il retrouve les coordonnées utiles, l’adresse, la nature de la demande et les consignes transmises par le bureau.
>
> Le rapport technique guide la saisie étape par étape. Le technicien peut compléter les constatations, les contrôles réalisés, les équipements concernés, les conclusions et les recommandations. Il peut également joindre des photographies pour documenter précisément son intervention.
>
> L’objectif n’est pas seulement de remplacer le papier. Il s’agit de produire un dossier plus homogène, plus lisible et plus facilement exploitable par le bureau.
>
> Pour éviter les modifications concurrentes, le rapport est protégé lorsqu’un utilisateur est en train de l’éditer. Les autres collaborateurs peuvent connaître son état sans écraser le travail en cours.
>
> Avant la validation finale, une relecture est demandée aux rôles autorisés. Cette étape permet de contrôler le contenu destiné au client et de limiter l’envoi d’un rapport incomplet ou comportant une erreur.
>
> Une fois validé, le rapport peut être présenté sous forme de PDF. Le document rassemble les informations du dossier, les constatations et les éléments visuels dans un format professionnel.
>
> La bibliothèque technique complète ce parcours : elle permet au technicien de consulter des notices et documents utiles, y compris lorsque certaines ressources ont été préparées pour un usage hors connexion.

### Messages clés

- saisie guidée sur mobile ;
- photographies et constatations intégrées ;
- contrôle avant validation ;
- rapport PDF professionnel ;
- documentation technique accessible sur le terrain.

### Conseil de présentation

Ne remplissez pas toutes les sections pendant la démonstration. Montrez seulement trois étapes représentatives puis ouvrez un rapport déjà terminé. Vous conserverez ainsi un rythme dynamique.

### Transition

> Le dossier technique étant constitué, regardons comment l’entreprise poursuit le traitement administratif.

## Séquence 6 — Devis, facture et suivi administratif

**Durée : 4 minutes**

### Manipulations

1. Ouvrir la partie **Facturation**.
2. Montrer un devis lié au client.
3. Montrer sa transformation ou son suivi jusqu’à la facture.
4. Présenter brièvement les statuts de paiement et l’archivage PDF.
5. Selon le public, ouvrir rapidement la partie comptable sans afficher de données confidentielles.

### Texte proposé

> Les informations du client peuvent ensuite être utilisées pour préparer le devis et poursuivre jusqu’à la facture, sans reconstruire le dossier depuis le début.
>
> L’entreprise peut suivre l’état de ses documents et de ses règlements. Les PDF restent rattachés au parcours administratif, ce qui facilite leur consultation ultérieure.
>
> La partie comptable propose un registre persistant et des contrôles destinés à structurer les écritures. Un export FEC peut être préparé avec des vérifications préalables. Comme pour tout export réglementaire, sa validation finale doit être réalisée avec le professionnel comptable de l’entreprise.
>
> Dépann’Home Pro prépare également le suivi nécessaire aux échanges de facturation électronique. Le choix et le contrat avec une plateforme agréée restent du ressort de l’entreprise.
>
> Le régime fiscal est configurable par entreprise. Une structure en franchise en base travaille automatiquement avec une TVA à 0 % et la mention « TVA non applicable, art. 293 B du CGI » apparaît sur les devis et factures intégrés. Une entreprise assujettie conserve ses taux par ligne et peut renseigner son numéro de TVA intracommunautaire.

### Messages clés

- continuité entre client, devis et facture ;
- suivi des règlements ;
- documents conservés ;
- données préparées pour le travail comptable.

### À ne pas promettre

- ne pas présenter Dépann’Home Pro comme remplaçant l’expert-comptable ;
- ne pas annoncer qu’une plateforme agréée est automatiquement incluse ;
- ne pas présenter un environnement Sandbox comme une comptabilité réelle.

### Transition

> Jusqu’ici, nous avons suivi une demande directe. Voyons maintenant comment l’entreprise peut également recevoir du travail depuis son réseau ou depuis un logiciel externe.

## Séquence 7 — Réseau et partenaires externes

**Durée : 4 minutes**

### Manipulations

1. Ouvrir **Missions partenaires**.
2. Montrer les espaces **Réseau Depann’Home Pro** et **Connecteurs externes**.
3. Expliquer la différence entre les deux modes.
4. Montrer une mission reçue et son changement de statut.
5. Si une Sandbox est utilisée, annoncer clairement qu’il s’agit de données fictives isolées.

### Texte proposé

> Dépann’Home Pro distingue deux formes de collaboration.
>
> Premièrement, le réseau Depann’Home Pro permet à des entreprises utilisatrices de se connecter et de collaborer dans l’application. Elles peuvent transmettre des missions et suivre leurs échanges selon les droits prévus.
>
> Deuxièmement, un partenaire externe — par exemple une assurance, un donneur d’ordre ou une plateforme — n’a pas besoin d’utiliser Dépann’Home Pro. L’entreprise réceptrice crée elle-même un accès API dans ses paramètres, puis transmet au partenaire son endpoint et une clé secrète.
>
> Le partenaire continue à travailler depuis son propre logiciel. Son logiciel envoie la mission à l’API ; Dépann’Home Pro crée la mission et la fiche client dans l’entreprise destinataire. Les changements de statut peuvent ensuite être retournés au logiciel partenaire si celui-ci fournit une URL de callback.
>
> L’entreprise est autonome pour créer, tester, modifier, désactiver ou renouveler son accès. En cas de problème, elle peut solliciter le support sans transmettre sa clé complète.
>
> Ici, l’espace marqué Sandbox utilise volontairement des données fictives. Il permet de vérifier le circuit sans créer de clients, rendez-vous ou statistiques de production.

### Messages clés

- collaboration entre entreprises du réseau ;
- connexion possible avec le logiciel d’un partenaire extérieur ;
- aucune interface Depann’Home Pro imposée au partenaire externe ;
- autonomie de configuration pour l’entreprise réceptrice ;
- séparation stricte entre tests et production.

### Consigne de sécurité

Ne jamais afficher une clé API pendant une présentation. Si une clé apparaît à l’écran ou sur une photographie, la renouveler immédiatement.

### Transition

> Cette circulation des informations nécessite enfin des règles d’accès et de traçabilité adaptées.

2. Montrer sans détail sensible la gestion des rôles, appareils ou journaux disponibles.
3. Revenir à l’accueil pour conclure.

### Texte proposé

> Chaque entreprise dispose de son propre espace de données. Les accès sont associés à des rôles afin que les collaborateurs utilisent uniquement les fonctions nécessaires à leur activité.
>
> La gestion des appareils, les mécanismes de validation et l’authentification renforcée disponible pour l’entreprise participent à la protection des comptes. Les opérations sensibles et les historiques métier permettent également de conserver une traçabilité.
>
> En trente minutes, nous avons suivi un parcours complet : création ou réception du client, planification, intervention mobile, rapport technique, devis, facture et échanges partenaires.
>
> La valeur de Dépann’Home Pro réside dans cette continuité. Le bureau organise, le technicien documente, l’administration poursuit le traitement et le dirigeant conserve une vision structurée de l’activité.
>
> L’objectif concret est de réduire les ressaisies, de fiabiliser les dossiers et de rendre les informations accessibles au bon collaborateur au bon moment.
>
> Je vous propose maintenant de répondre à vos questions et, si vous le souhaitez, de reprendre plus en détail le parcours qui correspond le mieux à votre organisation.

### Phrase de clôture

> Dépann’Home Pro relie le client, le bureau, le terrain et les partenaires autour d’un même dossier d’intervention.

# Questions fréquentes après la démonstration

## Le partenaire externe doit-il acheter ou installer Dépann’Home Pro ?

Non. Il peut conserver son propre logiciel. L’échange s’effectue par API avec un endpoint et une clé propres à l’entreprise destinataire.

## Qui crée la connexion avec un partenaire externe ?

L’administrateur de l’entreprise réceptrice crée et gère son accès depuis ses paramètres. Le Créateur de la plateforme intervient seulement pour la supervision globale ou le support.

## Quand la mission et le client apparaissent-ils ?

La connexion apparaît dans les paramètres dès sa création. La mission et la fiche client de production apparaissent après le premier envoi valide effectué par le logiciel du partenaire.

## Peut-on tester sans mélanger les données réelles ?

Oui. Les environnements Sandbox sont clairement identifiés et leurs données sont isolées des listes et statistiques de production.

## Plusieurs personnes peuvent-elles modifier simultanément le même rapport ?

Le système protège le rapport avec un verrou d’édition : une personne édite pendant que les autres évitent d’écraser son travail.

## Le logiciel remplace-t-il le comptable ?

Non. Il structure les documents, le registre et les exports. Les obligations déclaratives et la validation réglementaire restent à contrôler avec le professionnel comptable.

## Que se passe-t-il sans connexion internet sur le terrain ?

Certaines fonctions et ressources sont conçues pour rester disponibles hors connexion et se synchroniser au retour du réseau. Il est conseillé de vérifier le chargement des dossiers nécessaires avant une intervention en zone blanche.

## Les données de plusieurs entreprises sont-elles mélangées ?

Non. Chaque entreprise possède son propre périmètre de données et ses droits d’accès. Une relation de groupe ne fusionne pas automatiquement les clients ou les éléments financiers.

# Variantes selon le public

Insister sur :

- la vision globale de l’activité ;
- la traçabilité ;
- la réduction des doubles saisies ;
- le suivi administratif ;

Insister sur :

- la fiche client ;
- le planning ;
- la continuité devis–facture ;
- la recherche des documents ;
- le suivi des missions partenaires.

## Présentation à une équipe technique

Insister sur :

- l’accès mobile ;
- les consignes d’intervention ;
- les photographies ;
- le rapport guidé ;
- la bibliothèque technique ;
- la réduction des comptes rendus papier.

## Présentation à un donneur d’ordre ou partenaire externe

Insister sur :

- l’envoi depuis son propre logiciel ;
- l’authentification par clé API ;
- la création automatique de la mission et du client ;
- les retours de statut par callback ;
- l’absence de compte Depann’Home Pro obligatoire ;
- les essais préalables en Sandbox.

# Bonnes pratiques d’animation

- parler en bénéfices métier avant de détailler une fonction ;
- suivre un seul dossier fictif du début à la fin ;
- éviter de lire toutes les options affichées ;
- annoncer chaque changement de rôle : « nous sommes maintenant côté technicien » ;
- garder les modules Créateur hors du parcours standard ;
- annoncer clairement toute donnée Sandbox ;
- ne jamais improviser avec des données réelles ;
- prévoir un temps de questions après les trente minutes ;
- noter les besoins spécifiques sans promettre immédiatement une fonction non vérifiée.
